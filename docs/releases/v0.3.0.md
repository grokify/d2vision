# v0.3.0

**Release Date:** 2026-09-28

Adds datasheet-style infographic cards with animated flow dots, the ability to
derive a card's diagrams from protocol files, and an `svg2gif` command that turns
any animated SVG into a looping GIF.

## Highlights

- New `card` command: render a JSON card definition to an animated SVG, PNG, or looping GIF
- Sequenced flows: number the steps and the timing, loop length and step badges are derived
- Panels derived from [PIDL](https://github.com/grokify/pidl) protocol files, so a diagram cannot drift from its protocol
- New `svg2gif` command: convert any animated SVG (SMIL or CSS, including D2 animated edges) to a GIF

## Features

### Cards

A card is a fixed-size poster of stacked panels. Each panel pairs a short text
block with a simple node/edge diagram, or is a comparison table. The definition is
plain JSON, so many cards can go through the same pipeline.

- **`card render`**: writes an SVG, a PNG screenshot at a chosen point in the loop, and/or a looping GIF from one definition.
- **Flow dots**: edges can carry animated dots with a mode of `forward`, `reverse`, `alternate` (request/response), or `both` (full duplex), plus color, size, speed and count.
- **Steps and derived timing**: give flows a `step` and they run in order within a panel, with equal steps running together. Step badges number each edge, so the order reads in a static image. Leave `loop` unset and it is derived from the steps.
- **Protocol-backed panels**: a panel's `source` reads a PIDL file. You choose which actors and messages to show; the protocol file decides who sends each message to whom, and in what order. A step that does not exist, that contradicts the protocol order, or that has no edge to draw is an error. Steps that are not in the protocol file are drawn but reported as unverified warnings.
- **Artifacts and legend**: name each kind of message once with a color; the legend is derived from the artifacts actually used.
- **Deterministic and validated**: the same card always renders the same SVG. Rendering fails with a clear message instead of clipping when text or a table overflows its panel, a node falls outside its diagram area, or a flow does not fit an explicit loop.
- **Stable SVG ids** (`panel-*`, `node-*`, `edge-*`, `path-*`) so the output can be post-processed.

### svg2gif

- **`svg2gif`**: converts an animated SVG to a looping GIF for platforms that need one. Most SVG rasterizers ignore SVG animation, so this loads the SVG in headless Chrome, steps its animation clock (SMIL and CSS) one frame at a time, and encodes the result.
- Size comes from the SVG's `width`/`height` or `viewBox`, and the loop length from its longest animation; both can be overridden.
- Works on D2 diagrams that use `style.animated: true`.

### Export

- **`export.PNG`, `export.Frames`**: deterministic capture of an SVG at a given time, using headless Chrome.
- **`export.EncodeGIF`**: one shared palette with no dithering, and only the changed region of each frame stored with unchanged pixels transparent. A card with a few moving dots is a few hundred KB.
- **`export.InspectSVG`**: reads pixel size and loop length from an SVG.
- **`--chrome-no-sandbox`**: for environments where the calling process is itself sandboxed.

## Upgrading

v0.3.0 is backward compatible with v0.2.0. All additions are new commands and new
packages; existing APIs and command behavior are unchanged.

Adds the `github.com/chromedp/chromedp` dependency. Chrome or Chromium is needed
only for `card --png`, `card --gif` and `svg2gif`; SVG output and every existing
command work without it.
