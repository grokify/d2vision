# v0.4.0

**Release Date:** 2026-11-01

Makes `generate` safe for any label and any container layout, adds shared
classes, grid spacing, and a Mermaid flowchart writer, and takes three
dependency upgrades that change how TOON is written and how Chrome is driven.
The documentation moves to a standard layout.

This release has three breaking changes. They are listed first, with what to do
about each, in [Upgrading](#upgrading).

## Highlights

- `generate` writes every label as written, and an edge between nodes in different containers joins those nodes
- A diagram spec can be written as a Mermaid flowchart, and shared classes style D2 and Mermaid alike
- TOON output names fields by their JSON names (breaking for `.toon` files written with capitalized keys)
- chromedp v0.21.0, cdproto v0.159.0, and toon-go v1.0.1
- User guides moved under `docs/guides` (breaking for links to the documentation site)

## Features

### Labels that compile

A label with a character D2 reads as syntax (`:`, `;`, `{`, `}`, `#`, `$`, or a
quotation mark) used to produce D2 that did not compile, or that showed
something else. Such labels are now written in single quotes, where D2 does no
substitution, so they compile and appear exactly as given. A line break in a
label becomes a space.

### Edges between containers

An edge endpoint such as `stage.item` was written as one quoted name, which made
D2 create two new top-level nodes. A dot now separates the containers on the way
to a node, so `stage.item` is the node `item` in the container `stage`. Inside a
container, a name is relative to that container.

### Classes, spacing, and style

- **Classes**: `classes` names a style once, and a node, container, or edge uses it with `class`. They are written as D2 classes and as Mermaid `classDef`s, in name order, so the output is the same each time.
- **Grid spacing**: `horizontalGap` and `verticalGap` on the diagram and on a container set the space between grid cells, which an edge between columns needs.
- **Style fields**: `fontColor` and `bold`.

### Mermaid output

`generate.NewGenerator().Mermaid(spec)` writes a spec as a Mermaid flowchart.
Containers become subgraphs, a node is named by its whole path (Mermaid IDs are
global), and classes become `classDef`s. Mermaid has no grid, so `gridColumns`
and `gridRows` are ignored, and a spec with sequences or tables is refused with
an error.

This is a library function. The `generate` command still writes D2.

### Library

- New fields on `DiagramSpec`: `Classes`, `HorizontalGap`, `VerticalGap`. New fields on `ContainerSpec`, `NodeSpec`, and `EdgeSpec`: `Class` (and the gaps, on `ContainerSpec`). New fields on `StyleSpec`: `FontColor` and `Bold`. See the [API reference](../guides/api-reference.md).

### Documentation

- A [case study](../design/case-studies/fix-forward-chromedp-cdproto-toon.md) on fixing forward through the three upgrades in this release, including how the upstream projects ship.
- The guides cover labels, edge paths, classes, grid spacing, Mermaid output, and the TOON key names, and troubleshooting has an entry for the TOON change.
- The `generate` page no longer says the input format is detected from the file name. The default is TOON, and JSON and YAML are named with `-f`.

## Fixes

- `generate` output that did not compile because of a label.
- `generate` creating new top-level nodes for an edge between containers.

## Upgrading

### TOON keys are now lowercase

toon-go v1.0 names a struct field by its JSON name, where the earlier version
used the Go field name. TOON written by `parse`, `learn`, and `template` now has
keys like `version`, `viewBox`, and `nodes`.

A `.toon` spec written with the old capitalized keys (`Nodes`, `Edges`,
`GridColumns`) has no keys the reader recognizes, so `generate` prints nothing
and does not report an error. Rename the keys to lowercase, or write the spec
again with `learn` or `template`. JSON and YAML specs are not affected.

### Documentation URLs changed

The guides, commands, cookbook, examples, API reference, lint rules, and
troubleshooting pages moved under `guides/`, and the case study is under
`design/case-studies/`. A link to the old address, such as `/commands/lint/`,
is now `/guides/commands/lint/`. The lint rule documentation that `lint
--explain` points to moved with them.

### Dots in node names

An edge endpoint with a dot is now a path, so a node whose own ID contains a
dot cannot be named by an edge. Rename such a node, for example `node.1` to
`node_1`. IDs without dots are unaffected.

### Dependencies

chromedp moves to v0.21.0, cdproto to v0.159.0, and toon-go to v1.0.1. These are
breaking upstream and are fixed forward here, so programs that import d2vision's
`export` package and also use chromedp directly need chromedp's
[migration guide](https://github.com/chromedp/chromedp/blob/main/docs/MIGRATION.md).
Chrome or Chromium is still needed only for `card --png`, `card --gif`, and
`svg2gif`.
