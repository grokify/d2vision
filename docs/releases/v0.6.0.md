# v0.6.0

**Release Date:** 2026-11-12

Adds a way to tell whether a diagram can be read where it will be shown, and
the generator features that make a readable diagram: wrapped labels, boxes of
one width, and a layout engine that routes arrows around boxes. The parser now
reads diagrams whose elements have classes, which before parsed empty.

## Highlights

- `d2vision legibility` and the `legibility` package check whether a diagram's labels can be read on a Word page, a slide, or a screen, and find arrows drawn over boxes
- `generate` keeps line breaks in labels, fixes a class's box size, and can name the layout engine in the diagram
- The parser reads diagrams that give elements classes, and records each label's font size and lines

## Features

### Legibility

A diagram is scaled to fit the page or slide it is shown on, keeping its shape,
so a wide diagram on a narrow page shrinks and its labels with it.
`d2vision legibility` reads a D2-generated SVG, works out the size each label
is shown at on each target, and compares it with the smallest size that reads
comfortably there:

| Target | Area | Smallest label |
|--------|------|----------------|
| `docx-portrait` | Word, US Letter portrait, 1-inch margins | 9 pt |
| `docx-landscape` | Word, US Letter landscape, 1-inch margins | 9 pt |
| `tabloid-landscape` | Tabloid landscape, 1-inch margins | 9 pt |
| `slide-16x9` | 16:9 slide below a title | 18 pt |
| `screen` | Browser window, 1280 x 720 CSS pixels | 9 pt (12 px) |

```bash
d2vision legibility diagram.svg                          # every target
d2vision legibility diagram.svg -t docx-portrait --check # fail if not clear
d2vision legibility diagram.svg --width 8 --height 5 --min-font 10
```

For a diagram that is not readable, the report says how many times too wide or
tall it is, the largest size it can be with its smallest label still readable,
and what would help: wrapping long labels, fewer columns or rows, a larger
font, splitting it, or a target it already fits. It also lists every arrow
drawn over a box that is neither of its ends; a grid draws arrows straight,
over whatever is in the way, and ELK routes them around. `--check` exits with
status 1 on either problem. Output is text, JSON, or TOON.

In Go, `legibility.Analyze` returns the report for one target and
`legibility.Crossings` the arrows over boxes. `legibility.Wrap` breaks a label
into lines for a narrower box. The package reads the SVG and does not link the
D2 engine.

### Generate

- **Line breaks in labels.** A label with line breaks keeps them: it is written as a double-quoted D2 string with each break as `\n`, escaping backslashes, double quotes, and dollar signs so D2 shows them as written. Mermaid shows a break as `<br/>`. Before, a break became a space.
- **Box size.** `StyleSpec.Width` and `Height` fix the size of every shape of a class, so boxes line up in columns.
- **Layout engine.** `DiagramSpec.LayoutEngine` writes the engine into the diagram's `d2-config`, so `d2` draws it with, for example, ELK unless told otherwise.

### Parser

- Each node's `Style.FontSize` is its label's font size, and `LabelLines` holds a label's lines when it has more than one. A shape nested in `<g class="shape">` gives its fill and stroke.
- Edge paths follow curves and rounded corners (`C`, `S`, `Q`, `T`, `H`, `V`), sampling each curve, not only `M` and `L` points.

### Dependencies

chromedp moves to v0.23.0 and cdproto to v0.160.0, and the indirect
dependencies are updated. d2vision's own API does not change with them.
Chrome or Chromium is still needed only for `card --png`, `card --gif`, and
`svg2gif`.

## Fixes

- **Diagrams with classes parsed empty.** D2 writes an element's own classes after its base64 ID, as in `class="YQ== stage"`, so a diagram that used classes parsed with no nodes or edges. The parser now reads the first class name, and its fallback scan looks only at groups.
- **`learn` failed on a styled node.** A parsed node with a fill or stroke made `learn` write through a nil style pointer.

## Upgrading

v0.6.0 is backward compatible with v0.5.0. An API comparison reports only
additions: the `legibility` package, `Node.LabelLines`,
`generate.DiagramSpec.LayoutEngine`, and `generate.StyleSpec.Width` and
`Height`.

Two changes in output:

- `generate` keeps line breaks in labels where it used to turn them into spaces. A spec whose labels have no line breaks gives the same D2 as before.
- `parse` now finds the nodes and edges of diagrams whose elements have classes, and reports font sizes and the fill and stroke of nested shapes, so its output for such diagrams is fuller.

Programs that also use chromedp directly get v0.23.0 with this release.
